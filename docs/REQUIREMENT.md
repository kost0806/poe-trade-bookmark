# 요구사항 명세 (PoE Trade Bookmark)

PoE Trade Bookmark(`v0.6.0`)가 **무엇을 해야 하는가**를 정한 문서입니다. 어떻게
그렇게 하는지는 [설계 문서](DESIGN.md)에 있습니다. 각 항목 끝의 괄호는 그 요구사항을
맡고 있는 파일입니다.

- 우선순위 **필수**: 없으면 확장이 제 역할(§1의 핵심 목적)을 못 하는 것
- 우선순위 **권장**: 없어도 돌아가지만 실사용에서 불편이 큰 것
- 우선순위 **선택**: 편의 기능

---

## 1. 배경과 목적

**핵심 목적: PoE의 복잡한 검색을 기억해 두었다가, 다음에 그 검색을 편하게 다시 하는 것.**

거래소 검색은 조건을 쌓는 데 품이 많이 듭니다. 아이템 유형·희귀도·지도 등급 같은
드롭다운을 고르고, 최소/최대 칸을 채우고, 능력치 행을 여러 개 올려 그룹으로 묶습니다.
그런데 이렇게 만든 조건은 **한 번 쓰고 사라집니다.**

- 조건은 **주소에 담기지 않습니다.** 서버에 등록된 검색 ID에 묶여 있고, 화면에는
  페이지의 폼으로만 남습니다.
- 그래서 브라우저 기본 북마크로 저장해도 **무슨 검색인지 알 수 없는 주소**만 남습니다.
  나중에 목록에서 그것을 골라야 할 때 조건이 보이지 않습니다.
- 저장해 두지 않았다면 방금 한 검색이라도 조건을 처음부터 다시 넣어야 합니다.

이 확장은 그 검색을 **기억하는 일**과 **다시 꺼내 쓰는 일**을 거래소 페이지 안에서
해결합니다. 셋으로 나뉩니다.

| 단계 | 하는 일 | 대응 요구사항 |
| --- | --- | --- |
| 기억한다 | 남길 검색을 이름을 붙여 북마크로 저장하고, 남기지 않은 검색도 자동으로 기록에 쌓는다 | §3.2, §3.3 |
| 알아본다 | 저장한 것이 **무슨 검색인지** 이름과 요약으로 알아볼 수 있게 한다 — 조건을 폼에서 읽어 이름을 짓고 툴팁으로 보인다 | §3.4 |
| 다시 한다 | 목록에서 눌러 그때의 조건이 그대로 복원된 결과로 이동한다 | FR-BM-05, FR-HIST-01 |

`§3.4`(조건 읽기·요약·기본 이름)가 이 목적의 중심입니다. 조건을 알아볼 수 없는
저장은 저장하지 않은 것과 다르지 않고, 그것이 곧 브라우저 기본 북마크로는 안 되는
이유이기 때문입니다.

### 곁가지 목적

핵심은 아니지만 같은 자리(거래소 페이지 안)에서 해결하는 편이 나아 함께 넣은 것들입니다.
이 둘이 없어도 확장은 제 목적을 다합니다.

| 기능 | 왜 여기에 있나 |
| --- | --- |
| **16T 8모드 검색 만들기** (§3.5–3.9) | 조건이 정해져 있으면서 손으로 쌓기에는 가장 번거로운 검색이다 — 기억해 두는 것을 넘어 **아예 만들어 준다**. 대응하는 인게임 정규식까지 함께 얻는다 |
| **영문 아이템 복사** (§3.10) | 한글 거래소의 아이템은 PoB에 붙여넣을 수 없다. 검색해서 매물을 보는 흐름 안에서 바로 필요한 일이다 |

### 대상 사용자

PoE1을 한국 서버(`poe.kakaogames.com`) 또는 해외 서버에서 플레이하며, **조건이 여러 줄
되는 검색을 반복해서 쓰는** 사람. 특히 지도 파밍을 위해 8모드 지도를 사고 창고
정규식을 쓰는 사용자.

## 2. 범위

### 2.1 대상 (In scope)

| 항목 | 값 |
| --- | --- |
| 플랫폼 | 크롬 확장 (Manifest V3, `minimum_chrome_version` 102 이상) |
| 대상 게임 | Path of Exile **1** |
| 대상 사이트 | `poe.kakaogames.com`, `poe.game.daum.net`, `www.pathofexile.com` 및 언어권 서브도메인(`kr.`, `jp.`, `ru.`, `de.`, `fr.`, `es.`, `br.`, `th.`) |
| 대상 경로 | `/trade/search/...` (일반 검색) |
| UI 언어 | 한국어 |

### 2.2 비대상 (Out of scope)

- **PoE2 (`/trade2/`)** — 폼 구조와 API가 다르므로 대상이 아닙니다.
- **대량 거래(`/trade/exchange/`)** — 인게임 가판대가 생긴 뒤로 쓰임이 크게 줄었습니다.
  주소를 인식해 저장은 되지만(폼 구조가 달라 조건은 읽지 못합니다) 기능을 맞추지 않습니다.
- 거래 자동화, 매물 감시·알림.
- 계정 로그인 정보를 요구하는 기능. 확장은 자격 증명을 다루지 않습니다.
- 서버·클라우드 동기화. 저장은 로컬에만 합니다(§7).

## 3. 기능 요구사항

### 3.1 사이드바 (FR-PANEL)

| ID | 우선순위 | 요구사항 |
| --- | --- | --- |
| FR-PANEL-01 | 필수 | 거래소 페이지에 **페이지 내부 사이드바**를 심는다. 크롬 사이드 패널 API나 툴바 팝업은 쓰지 않는다 — 거래소를 보면서 동시에 조작해야 하기 때문. (`panel.js`) |
| FR-PANEL-02 | 필수 | 화면 오른쪽 끝에 세로 손잡이(`◀`/`▶`)를 띄우고, 눌러 열고 접는다. 툴바 아이콘은 제공하지 않는다. |
| FR-PANEL-03 | 필수 | 열면 사이드바가 거래소 화면을 **덮지 않고 밀어낸다**. 문서를 밀 때 건드리는 것은 `<html>`의 `margin-right` 하나뿐이다. |
| FR-PANEL-04 | 필수 | 폭은 `min(360px, 50vw)` — 창이 좁으면 화면 절반을 넘지 않는다. |
| FR-PANEL-05 | 권장 | 접기/펼치기 상태를 저장해 페이지를 옮겨도 유지한다. **기본값은 접힘** (거래소 화면을 처음부터 좁히지 않기 위해). |
| FR-PANEL-06 | 필수 | 대상 사이트의 `/trade/` 경로에서만 실행되고, 그 외 사이트에는 아무것도 주입하지 않는다. |
| FR-PANEL-07 | 필수 | 사이드바는 **Shadow DOM** 안에서 그린다. 거래소 CSS와 서로 영향을 주지 않아야 한다. |
| FR-PANEL-08 | 필수 | 사이드바 안에서 누른 키는 거래소의 전역 단축키로 새어 나가지 않는다(`keydown`/`keyup`/`keypress` 차단). |
| FR-PANEL-09 | 권장 | 스타일은 코드로 만든 `CSSStyleSheet`(`adoptedStyleSheets`)로 주입해 거래소의 CSP(`style-src`)에 막히지 않게 한다. 스타일을 못 읽어도 **기능은 계속 동작한다**. |

### 3.2 북마크 (FR-BM)

| ID | 우선순위 | 요구사항 |
| --- | --- | --- |
| FR-BM-01 | 필수 | 현재 주소가 `.../trade/<search\|exchange>/<리그>/<검색ID>` 형태일 때만 저장할 수 있다. 검색 ID가 없으면 저장 폼 대신 안내 문구를 보인다. |
| FR-BM-02 | 필수 | 이름을 입력해 **북마크 추가**로 저장한다. 이름을 비우면 검색 ID로 만든 이름을 쓴다. 이름 한도는 80자. |
| FR-BM-03 | 필수 | 이미 저장한 검색을 다시 열면 저장된 이름이 채워지고 버튼이 **이름 변경**으로 바뀐다. 이때 저장하면 새 항목을 만들지 않고 **이름만 갱신**한다(같은 URL = 같은 북마크). |
| FR-BM-04 | 권장 | 이름이 비었거나 저장된 이름과 같으면 버튼을 잠근다. |
| FR-BM-05 | 필수 | 목록 항목을 누르면 **현재 탭**이 그 검색으로 이동한다. |
| FR-BM-06 | 필수 | 항목마다 **삭제** 버튼을 둔다. |
| FR-BM-07 | 권장 | 항목에 마우스를 올리면 그 검색의 **조건 요약**을 툴팁으로 보인다(§3.4). 요약이 없으면 주소를 보인다. |
| FR-BM-08 | 권장 | 8모드 빌더로 만든 검색을 저장하면 인게임 정규식도 함께 보관하고, 목록의 **정규식** 버튼으로 언제든 다시 복사할 수 있다. |
| FR-BM-09 | 권장 | 다른 탭에서 추가·삭제·이름 변경한 내용이 열려 있는 모든 사이드바에 즉시 반영된다(`storage.onChanged`). |
| FR-BM-10 | 권장 | 요약이 붙기 전에 저장한 북마크라도, 그 검색에서 이름을 다시 저장하면 그때 요약을 채워 넣는다. |

### 3.3 검색 기록 (FR-HIST)

| ID | 우선순위 | 요구사항 |
| --- | --- | --- |
| FR-HIST-01 | 필수 | 거래소에서 **직접 실행한 검색**은 저장하지 않아도 자동으로 기록에 쌓인다. |
| FR-HIST-02 | 필수 | **사이드바에서 눌러 이동한 검색(북마크·기록)은 기록에 남기지 않는다.** 8모드 빌더로 만든 검색은 직접 한 검색이므로 남긴다. |
| FR-HIST-03 | 필수 | 같은 검색(같은 URL)은 새로 쌓지 않고 **맨 위로 올린다**. 거래소는 조건이 같으면 같은 검색 ID를 돌려주므로 반복 검색으로 목록이 채워지면 안 된다. |
| FR-HIST-04 | 필수 | 최대 **50개**를 유지하고 오래된 것부터 밀어낸다. |
| FR-HIST-05 | 권장 | 항목별 **삭제**와 전체 **기록 비우기**를 제공한다. |
| FR-HIST-06 | 권장 | 항목에는 리그·검색 종류·마지막 검색 시각(시:분까지)을 함께 보인다. 기록은 같은 날 여러 번 쌓이므로 날짜만으로는 구분되지 않는다. |
| FR-HIST-07 | 권장 | 기록 절은 **기본 펼침** 상태이고, 접기 상태를 저장한다. |
| FR-HIST-08 | 필수 | 이동 표식(사이드바에서 이동했다는 표시)은 한 번만 쓰고 버리며, 주소가 일치할 때만 소비한다. 오래된 표식(60초 초과)은 무시한다 — 다른 탭이 대신 써 버리면 안 되기 때문. |

### 3.4 검색 조건 읽기 · 요약 · 기본 이름 (FR-SUM)

| ID | 우선순위 | 요구사항 |
| --- | --- | --- |
| FR-SUM-01 | 필수 | 검색 조건은 **네트워크 요청 없이 페이지의 검색 폼(DOM)에서만** 읽는다. (`search-summary.js`) |
| FR-SUM-02 | 필수 | 읽는 대상은 사용자가 고르거나 입력한 값뿐이다 — 검색창 아이템, 고른 드롭다운 필터, **값이 든** 최소/최대 칸, 능력치 그룹. 리그·상태 드롭다운은 조건이 아니므로 제외한다. |
| FR-SUM-03 | 필수 | 능력치는 **그룹 제목(`모두 일치`, `일치 없음`, `개수` …)과 함께** 적는다. 같은 스탯이라도 찾는 조건인지 거르는 조건인지에 따라 뜻이 정반대이므로, 제목을 빼면 요약이 거짓이 된다. |
| FR-SUM-04 | 권장 | 값 표기: 최소만 `>= n`, 최대만 `<= n`, 둘 다 `n ~ m`, 같으면 `= n`. `유사`/`비고정` 같은 스탯 종류 딱지는 `(유사) …` 형태로 앞에 붙인다. |
| FR-SUM-05 | 권장 | 툴팁 요약은 최대 **14줄**까지 보이고, 넘으면 자른 뒤 남은 줄 수를 알린다. |
| FR-SUM-06 | 필수 | 읽어 낸 조건으로 북마크 **기본 이름**을 짓는다(`search-name.js`). 검색창 아이템이 있으면 그것, 없으면 조건을 `·`로 이어 붙인다. 능력치는 행이 하나면 그 스탯, 여럿이면 `제외 12개`처럼 접는다. 80자를 넘으면 뒷부분을 버린다. |
| FR-SUM-07 | 필수 | 폼이 아직 채워지기 전일 수 있으므로(북마크 링크로 새 탭을 열었을 때) **0.25초 간격으로 8회까지 다시 읽는다.** 끝내 못 읽으면 검색 ID로 만든 이름(`<리그> 검색 <검색ID>`)을 쓴다. |
| FR-SUM-08 | 필수 | **검색 내용이 바뀌면 추천 이름을 다시 채운다.** 조건이 같으면 같은 검색 ID가 오므로 주소만 보면 놓친다 — 폼에서 뽑은 이름이 달라졌는지도 함께 본다. |
| FR-SUM-09 | 필수 | 다음 이름은 자동 갱신이 **건드리지 않는다**: 이미 저장된 북마크의 이름, 빌더가 지어 준 이름, 사용자가 직접 고친 이름(단 검색 자체가 바뀌면 갱신). |
| FR-SUM-10 | 필수 | 요약은 표시 문구가 아니라 **읽어 낸 구조 그대로** 저장한다. 표시 형태를 바꿔도 이미 저장한 항목이 그 형태를 따라오게 하기 위함(§7). |

### 3.5 16T 8모드 검색 빌더 (FR-BUILD)

| ID | 우선순위 | 요구사항 |
| --- | --- | --- |
| FR-BUILD-01 | 필수 | 거를 맵모드를 고르면 **거래소 검색**과 **인게임 정규식**을 동시에 만든다. 둘은 같은 선택에서 나오므로 서로 어긋나지 않아야 한다. |
| FR-BUILD-02 | 필수 | 거래소 검색은 `POST /api/trade/search/<리그>`로 등록하고, 돌아온 id로 만든 결과 주소로 현재 탭을 이동한다. 거래소는 URL 파라미터로 조건을 받지 않으므로 다른 방법이 없다. |
| FR-BUILD-03 | 필수 | 만들어지는 검색 조건: 아이템 유형 `지도`, 희귀도 `모든 비고유(nonunique)`, 지도 등급 `16`(min=max), `# 속성 부여` **8개 이상**, 거래 옵션 **즉시 구입(securable)** — 귓속말을 기다리지 않고 가판대에서 바로 살 수 있는 매물만, 정렬 **가격 오름차순**. |
| FR-BUILD-04 | 필수 | **영향력 받은 지도를 제외한다.** 거래소 필터에 영향력 항목이 없고 pseudo 영향력 스탯이 지도에 걸리지 않으므로, implicit stat id 8종(쉐이퍼·엘더·정복자 4종·전체·근원의 기억)을 `not` 그룹으로 직접 뺀다. |
| FR-BUILD-05 | 필수 | 고른 모드는 **하나의 `not` 스탯 그룹**에 모두 넣는다. |
| FR-BUILD-06 | 필수 | 리그는 `/api/trade/data/leagues`에서 받아 드롭다운으로 고른다(PC 리얼름만). 결과는 **origin별로 24시간 캐시**하고, 실패하면 미리 박아 둔 목록으로 대체한다. |
| FR-BUILD-07 | 필수 | 검색 등록은 **2.5초 최소 간격**을 둔다. `429`를 받으면 `Retry-After` 값을 그대로 안내한다(§6.3). |

### 3.8 인게임 정규식 (FR-REGEX)

| ID | 우선순위 | 요구사항 |
| --- | --- | --- |
| FR-REGEX-01 | 필수 | 고른 모드로 `!키워드\|키워드…` 형태의 인게임 정규식을 만든다. 각 키워드는 **그 모드에만 매칭되는 최단 부분문자열**이고, 공백 자리는 `.`으로 쓴다. |
| FR-REGEX-02 | 권장 | 키워드는 **짧은 것부터** 이어 붙인다 — 한도에서 잘려도 더 많은 모드가 살아남도록. |
| FR-REGEX-03 | 필수 | **역방향**: 인게임 정규식을 붙여넣으면 그에 걸리는 모드가 목록에서 그대로 선택된다. 이 확장이 만든 것뿐 아니라 다른 도구(poe.re 등)에서 받은 것도 해석한다. |
| FR-REGEX-04 | 필수 | 붙여넣은 정규식이 곧 선택 전체이므로 **기존 선택을 대체한다**. 넓은 패턴이 여러 모드에 걸리면 전부 선택한다(인게임에서도 전부 숨겨지므로 그게 맞다). 어느 모드에도 안 걸리는 패턴은 따로 알린다. |
| FR-REGEX-05 | 필수 | 정규식 해석은 **게임 엔진(MSVC `std::regex`, ECMAScript 문법)의 실제 동작**을 따른다. JS의 `RegExp`에 그대로 넘기지 않는다 — 넘기면 "걸린다"고 표시한 지도가 인게임에서는 안 걸리는 어긋남이 생긴다. |
| FR-REGEX-06 | 필수 | 게임과 맞춰야 하는 세 가지: ① **한 줄씩** 매칭(`.`은 줄바꿈을 넘지 않고 `^`/`$`는 줄마다), ② 정규식 해석 전에 **글자 그대로(부분 문자열) 먼저** 찾음 — 문법이 깨진 패턴도 오류로 막지 않음, ③ 인게임 고유 문법(공백=AND 구분, `!`=항목 부정, `"…"`=묶음). |
| FR-REGEX-07 | 필수 | 게임에서 통하는지 **알 수 없는 문법은 매칭에서 빼고 따로 알린다** — 후방 탐색(`(?<=)`, `(?<!)`, MSVC에 구현 없음), 역참조(`\1`), 단어 경계(`\b`). 찍어서 맞추면 확장만 걸린다고 하는 어긋남이 생긴다. |
| FR-REGEX-08 | 필수 | 매칭은 되추적이 아니라 **NFA 시뮬레이션**으로 한다. 검색칸에는 아무 정규식이나 붙여 넣을 수 있으므로, `(가+)+나` 같은 패턴 하나에 사이드바가 멈추면 안 된다. |
| FR-REGEX-09 | 권장 | 모드 문구의 수치 구간(`(22—25)%`)은 실제 아이템에서 한 값(`23%`)으로 찍히므로, **구간을 채운 표본에도 대조**해 `피해...%` 같은 패턴을 놓치지 않는다. |

### 3.9 맵모드 데이터와 검증 (FR-DATA)

| ID | 우선순위 | 요구사항 |
| --- | --- | --- |
| FR-DATA-01 | 필수 | 각 모드는 `{ ids, regex, group, affix, text }`를 갖는다. `ids`가 여럿인 항목은 인게임 문구로 구분되지 않는 같은 계열이다. 타락으로 붙는 모드는 `explicit`이 아니라 **`implicit`** 이다 — domain을 틀리면 거래소는 안 걸러 주는데 인게임만 숨긴다. |

| FR-DATA-04 | 필수 | 인게임 검색은 **고급 모드 설명 줄(접두어 이름·태그)까지 읽는다.** 이름·태그와 겹치는 키워드는 그 모드가 없는 지도까지 숨기므로, 안전한 부분문자열로 바꿔야 한다. |
| FR-DATA-05 | 권장 | 리그가 바뀌어 모드 풀이 달라지면 픽스처(`test/fixtures/`)를 다시 받아 갱신한다. |

### 3.10 영문 아이템 복사 (FR-EN)

| FR-EN-07 | 권장 | 결과 표시: 성공 `✓`, 실패 `!`. 실패 이유는 단추 툴팁에 남기고 잠시 뒤 원래 라벨로 되돌린다. 되돌리기 타이머는 단추마다 따로 잡아, 다른 줄을 이어 눌러도 앞 단추가 표시에 갇히지 않게 한다. |

| NFR-ROB-01 | 필수 | 거래소 마크업에 의존하는 선택자는 **한 파일에 모아** 둔다(`search-summary.js` 상단, `copy-en.js` 상단). 거래소가 마크업을 바꾸면 손볼 곳이 거기뿐이어야 한다. |
| NFR-ROB-02 | 필수 | 선택자가 어긋나도 **확장이 죽지 않는다.** 조건을 못 읽으면 검색 ID 이름과 주소 툴팁으로 물러서고, 결과 줄 선택자가 안 잡히면 대체 선택자를 쓴다. |
| NFR-ROB-03 | 권장 | DOM 변화 감시는 잠깐 모아서 한 번에 처리한다(디바운스). 결과가 스크롤로 계속 붙는 화면에서 매 변화마다 훑지 않는다. |
| NFR-ROB-04 | 필수 | 사용자가 붙여넣은 정규식 때문에 UI가 멈추는 일이 없어야 한다(FR-REGEX-08). |
| NFR-ROB-05 | 권장 | 거래소 페이지의 스타일·레이아웃을 바꾸지 않는다. 예외는 문서를 밀어내는 `margin-right` 하나와, 결과 줄이 `position: static`일 때 기준점을 세우는 것뿐이다. |

## 6. 데이터 모델 (`chrome.storage.local`)

확장을 삭제하면 함께 지워집니다. 동기화는 하지 않습니다.

| 키 | 내용 |
| --- | --- |
| `bookmarks` | 북마크 배열 |
| `history` | 검색 기록 배열 (최대 50) |
| `userPresets` | 내 프리셋 `{ id, label, keys, at }` |
| `builder` | 빌더 상태 `{ selected, league, open }` |
| `pending` | 방금 만든 검색 `{ url, title, regex, at }` (TTL 10분) |
| `nav` | 사이드바 이동 표식 `{ url, at }` (TTL 60초, 1회용) |
| `leagues` | 리그 목록 캐시 `{ origin, at, leagues }` (24시간) |
| `panelOpen` / `historyOpen` | 사이드바·기록 절 펼침 상태 |

북마크 한 건:

```json
{
  "id": "uuid",
  "title": "표시 이름",
  "url": "https://www.pathofexile.com/trade/search/<리그>/<검색ID>",
  "league": "리그명",
  "mode": "search | exchange",
  "searchId": "검색ID",
  "summary": {
    "item": "괴사의 방어구",
    "filters": [{ "label": "타락함", "value": "아니오" }],
    "ranges": [{ "label": "지도 등급", "type": "", "min": "16", "max": "16" }],
    "statGroups": [
      { "title": "모두 일치", "rows": [{ "label": "생명력 최대치 +#", "type": "", "min": "100", "max": "", "value": "" }] }
    ]
  },
  "regex": "!대상이|재사용",
  "createdAt": 1700000000000,
  "updatedAt": 1700000000000
}
```

- `summary`는 **보여 줄 문구가 아니라 읽어 낸 구조 그대로**입니다(FR-SUM-10). 조건을 못 읽었으면 아예 없습니다.
- `regex`는 8모드 빌더로 만든 검색에만 있습니다.
- 기록 항목은 `createdAt`/`updatedAt` 대신 마지막으로 검색한 때인 `at`을 갖습니다.

## 7. 수용 기준 (실제 거래소에서 확인)

자동 검사로 덮지 못하는, 사람이 눈으로 봐야 하는 것들입니다.

| # | 확인할 것 | 기대 |
| --- | --- | --- |
| A1 | 거래소를 연다 | 오른쪽 끝에 `◀` 손잡이가 뜨고, 눌러 열면 페이지가 그만큼 밀린다 |
| A2 | 검색을 실행한다 | 이름 칸이 검색 조건으로 채워지고, 기록 맨 위에 그 검색이 쌓인다 |
| A3 | 같은 검색을 다시 한다 | 기록이 늘지 않고 맨 위로만 올라온다 |
| A4 | 기록 항목을 누른다 | 그 검색으로 이동하고, **그 이동은 기록에 남지 않는다** |
| A5 | 저장한 검색을 다시 연다 | 저장한 이름이 채워지고 버튼이 **이름 변경**이다 |
| A6 | 목록 항목에 마우스를 올린다 | 조건 요약이 줄 단위로 뜨고, 드롭다운 필터 라벨(`타락함: 아니오`)이 보인다 |
| A7 | 모드 고르기 창을 연다 | 거래소 위에 제대로 뜨고, 밀어낸 여백이나 `overflow`에 잘리지 않는다 |
| A8 | 프리셋 저장 → 다시 선택 → 삭제 | 세 동작이 모두 반영되고 다른 탭에도 즉시 보인다 |
| A9 | 8모드 검색을 만든다 | 결과에 **고유 지도와 영향력 지도가 섞이지 않는다** |
| A10 | 만든 검색을 저장한다 | 정규식이 함께 보관되고 **정규식** 버튼으로 복사된다 |
| A11 | 다른 도구의 정규식을 붙여넣는다 | 걸리는 모드가 그대로 선택되고, 안 걸리는 패턴은 따로 알려 준다 |
| A12 | 한국 서버 결과에서 EN을 누른다 | 영문 텍스트가 복사되고 PoB에 그대로 붙는다(유니크·희귀·젬·플라스크·지도·클러스터 주얼) |
| A13 | 같은 아이템의 EN을 다시 누른다 | 요청 없이 즉시 복사된다 |

자동 검사: `node --test` (정규식 엔진 · 쿼리 생성 · 검색 요약), `node --check panel.js`.

## 8. 알려진 제약

| 제약 | 내용 |
| --- | --- |
| 대량 거래는 최소 지원 | 저장·이동은 되지만 조건 요약과 EN 복사는 없다. 비대상이므로 맞출 계획도 없다(§2.2). |
| 프리셋 이동 불가 | `chrome.storage.local`에만 있어 다른 컴퓨터로 옮길 방법이 없다. 내보내기/가져오기는 향후 과제. |
| 리그 교체 시 데이터 갱신 필요 | 모드 풀과 픽스처가 리그별 실측값이라 리그가 바뀌면 다시 받아야 한다(FR-DATA-05). |
| 무작위 지도 이름 미검증 | 희귀 지도의 무작위 이름 낱말 목록을 구할 수 없어, 키워드가 그 이름에 걸리는지는 검사로 막지 못한다. 한글 3글자 규칙으로 확률을 낮춘다(FR-DATA-02). |
| 거래소 마크업 의존 | 조건 읽기와 EN 단추 부착은 거래소 DOM 구조에 기댄다. 구조가 바뀌면 선택자를 손봐야 한다(NFR-ROB-01·02). |
