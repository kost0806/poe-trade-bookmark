# PoE Trade Bookmark

Path of Exile 1 거래소(Trade)를 쓰기 편하게 만드는 크롬 확장입니다. 검색 결과 URL을
북마크로 저장하고, 한글 거래소에서 본 아이템을 [영문으로 복사](#영문-아이템-복사-pob용)해
PoB에 바로 붙여넣을 수 있습니다.

한글 거래소와 영문 거래소를 모두 지원합니다([언어](#언어) 참고). 맵모드 목록과 인게임
정규식 키워드가 언어별로 따로 있어서, 어느 쪽에서 만들든 그 클라이언트에서 그대로
붙여넣을 수 있습니다.

## 설치 (개발자 모드)

1. 크롬에서 `chrome://extensions` 접속
2. 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드** → 이 폴더(`poe-trade-bookmark`) 선택

## 사용법

사이드바는 크롬 사이드 패널이 아니라 **거래소 페이지 안에** 붙습니다. 거래소를 열면
페이지 우측 상단에 세로로 긴 **◀** 손잡이가 나타나고, 누르면 화면 오른쪽 끝에 세로로
한 칸이 열립니다. 이때 페이지 내용은 그만큼 왼쪽으로 밀려나므로 거래소 화면을 가리지
않습니다. 손잡이는 사이드바 왼쪽 옆구리에 그대로 붙어 따라다니고, **▶** 를 누르면
다시 접히면서 페이지가 원래 폭으로 돌아갑니다.

다른 사이트로 옮기면 사이드바도 함께 사라집니다. 접기/펼치기 상태는 기억되므로
거래소 안에서 페이지를 옮겨도 유지됩니다. 칸 폭은 360px이고, 창이 좁으면 화면
절반까지만 차지합니다.

1. 거래소에서 검색을 실행합니다. 주소가
   `.../trade/search/<리그>/<검색ID>` 형태가 되어야 저장할 수 있습니다.
   (검색 전에는 검색 ID가 없어 저장 버튼이 나오지 않습니다.)
2. 사이드바에서 이름을 입력하고 **북마크 추가**를 누릅니다. 이름 칸은 거래소 검색
   폼을 읽어 미리 채워집니다(아래 [기본 이름](#기본-이름)).
3. 이미 저장한 검색을 다시 열면 저장해 둔 이름이 채워지고 버튼이 **이름 변경**으로
   바뀝니다. 이름을 고친 뒤 누르면 새 항목을 만들지 않고 이름만 바꿉니다.
4. 목록의 항목을 클릭하면 현재 탭이 그 검색으로 이동합니다.
5. 항목에 마우스를 올리면 어떤 조건으로 검색한 것인지 요약이 뜹니다
   (아래 [검색 조건 요약](#검색-조건-요약)).

저장하지 않은 검색도 [검색 기록](#검색-기록)에 저절로 쌓입니다.

툴바 아이콘은 없습니다. 사이드바는 거래소 페이지의 손잡이로만 열고 닫습니다.

### 검색 기록

거래소에서 **직접 한 검색**은 저장하지 않아도 사이드바 아래 **검색 기록**에 쌓입니다.
북마크는 남길 것을 골라 두는 자리라 검색할 때마다 손이 가지만, 기록은 아무것도 안
해도 남아서 "아까 그 검색"으로 되돌아갈 수 있습니다.

- 항목을 누르면 **그때의 검색어와 필터가 그대로 복원된 결과**로 이동합니다. 검색
  조건은 검색 ID에 묶여 서버에 있으므로, 주소만 있으면 조건을 재현할 필요가 없습니다.
- 같은 검색은 새로 쌓지 않고 맨 위로 올라옵니다. 거래소는 조건이 같으면 같은 검색
  ID를 돌려주므로, 같은 검색을 반복해도 목록이 그것으로 채워지지 않습니다.
- 최근 50개까지 남고 오래된 것부터 밀려납니다. 항목마다 **삭제**, 아래에 **기록 비우기**가
  있습니다.
- **사이드바에서 눌러 이동한 검색(북마크·기록)은 기록에 남지 않습니다.** 기록에 남는
  것은 거래소에서 직접 검색어와 필터를 넣어 실행한 검색뿐입니다. 사이드바의 8모드
  빌더로 만든 검색은 직접 한 검색이므로 남습니다.

### 검색 조건 요약

북마크와 기록 항목에 마우스를 올리면 그 검색의 조건이 줄 단위로 나옵니다.

```
괴사의 방어구
타락함: 아니오
[모두 일치]
생명력 최대치 +#: >= 100
(유사) 힘 총 #: >= 50
```

검색창의 아이템이 첫 줄이고, 그다음이 고른 드롭다운 필터와 값이 든 최소/최대 칸,
마지막이 능력치 필터입니다. 최소는 `>=`, 최대는 `<=`, 양쪽을 다 넣으면 `100 ~ 200`,
같은 값을 넣으면 `= 16`으로 적습니다.

능력치는 `[모두 일치]`, `[일치 없음]` 같은 **그룹 제목을 함께** 적습니다. 같은 스탯이라도
찾는 조건인지 거르는 조건인지에 따라 뜻이 정반대라, 빼면 요약이 거짓말이 됩니다.
14줄을 넘으면 뒤를 자르고 남은 줄 수를 알립니다.

조건을 못 읽었으면(요약이 붙기 전에 저장한 북마크, 폼 구조가 다른 대량거래) 예전처럼
주소가 뜹니다.

### 기본 이름

검색 조건은 주소에 남지 않고 폼에만 있습니다. 사이드바는 거래소 페이지 안에서 도는
콘텐츠 스크립트라, 요청 없이 폼을 그대로 읽습니다(`search-summary.js`). 그 조건으로
이름을 짓는 것이 `search-name.js`입니다 — 위의 요약과 읽는 자리가 같습니다.

| 검색 | 기본 이름 |
| --- | --- |
| 검색창에 아이템을 넣음 | `헤드헌터` |
| 조건만 지정 (16T 8모드) | `지도 · 지도 등급 16 · # 속성 부여 8+ · 제외 12개` |
| 아무것도 못 읽음 | `<리그> 검색 <검색ID>` |

조건으로 이름을 만들 때 쓰는 값은 사용자가 고르거나 입력한 것뿐입니다 — 고른
드롭다운 필터(아이템 유형, 희귀도 …), 값이 든 최소/최대 칸, 능력치 그룹(행이 하나면
그 스탯, 여럿이면 `제외 12개`처럼 그룹 제목과 개수). 80자를 넘으면 뒷부분을 버립니다.

거래소가 폼을 채우기 전일 수 있어(북마크 링크로 새 탭을 열었을 때) 0.25초 간격으로
여덟 번까지 다시 읽고, 그래도 못 읽으면 검색 ID로 만든 이름을 그대로 씁니다.
대량거래(`/trade/exchange/`)는 폼 구조가 달라 아직 검색 ID 이름을 씁니다.

이름을 직접 적어 둔 뒤라도 **검색을 바꾸면 추천 이름이 다시 채워집니다**. 거래소는
조건이 같으면 같은 검색 ID를 돌려주므로 다시 검색해도 주소가 그대로일 수 있어,
주소뿐 아니라 폼에서 뽑은 이름이 달라졌는지도 함께 봅니다. 검색이 그대로면 적어 둔
이름을 지키고, 이미 저장한 북마크의 이름은 어느 경우에도 건드리지 않습니다.

## 언어

사이드바 오른쪽 위의 고르개에서 **자동 / 한글 / English** 중 하나를 고릅니다. 기본은
자동이고, 지금 보고 있는 거래소의 호스트로 정합니다.

| 호스트 | 자동일 때 |
| --- | --- |
| `poe.kakaogames.com`, `poe.game.daum.net`, `kr.pathofexile.com` | 한글 |
| 그 밖의 모든 거래소(`www.pathofexile.com` 등) | 영문 |

바뀌는 것은 세 가지입니다.

1. 사이드바와 모드 고르기 창의 모든 문구
2. **맵모드 목록** — 한글판 `map-mods.js`, 영문판 `map-mods-en.js`
3. **인게임 정규식 키워드** — 아래 `!쇠약화|몬스터가.타`가 영문에서는
   `!Monsters.drop|with.Enfeeble`이 됩니다

키워드는 아이템 전문에 그대로 걸리는 글자라서 언어마다 다시 골라야 합니다. 한글
키워드는 영문 클라이언트에서 하나도 걸리지 않습니다. **인게임에서 쓸 클라이언트의
언어**로 맞춰 두세요 — 거래소를 어느 서버에서 보든, 정규식을 붙여넣을 곳은 게임입니다.

바뀌지 않는 것: 저장해 둔 북마크·검색 기록·프리셋. 프리셋은 모드를 거래소 stat id로
담고, 두 맵모드 목록이 같은 순서·같은 id라서 언어를 바꿔도 고른 모드가 그대로
남습니다(정규식만 그 언어의 키워드로 다시 만들어집니다).

영문 문구는 PoE 커뮤니티에서 흔히 쓰는 말을 따랐습니다 — `T16 8-mod`, `regex`,
`exclude`, `bulk exchange`.

## 영문 아이템 복사 (PoB용)

검색 결과의 줄에 마우스를 올리면 아이템 그림 오른쪽 아래에 **EN** 단추가 나옵니다.
누르면 그 아이템의 정보가 **영문으로** 클립보드에 들어가고, PoB의 아이템 붙여넣기
칸에 그대로 넣을 수 있습니다. 복사되면 ✓, 실패하면 ! 로 잠깐 바뀌며 실패 이유는
단추의 툴팁에 남습니다.

일반 검색(`/trade/search/`)에서만 나옵니다. 대량거래는 통화 묶음이라 붙이지 않습니다.

### 어떻게 정확한 영문이 나오나

거래소는 아이템 텍스트를 **보고 있는 사이트의 언어로만** 줍니다. 한국 서버나
`kr.pathofexile.com`에서는 스탯 문구가 전부 한글이라 PoB가 읽지 못합니다.

한글을 영문으로 옮기지 않습니다. 옮기면 어긋날 수 있기 때문입니다. 대신 아이템 ID가
서버·언어와 무관한 해시라는 점을 이용해, **같은 ID를 영문 거래소에 다시 물어봅니다.**

```
poe.kakaogames.com 검색 결과 → 아이템 ID
  → https://www.pathofexile.com/api/trade/fetch/<ID>
  → result[0].item.extended.text (base64) → 영문 아이템 텍스트
```

돌아오는 값은 GGG가 직접 만든 문구이고 줄바꿈까지 게임에서 Ctrl+C 한 것과 같은
형태(CRLF)라, 손대지 않고 그대로 클립보드에 넣습니다. 유니크·희귀·젬·플라스크·지도·
클러스터 주얼에서 한글이 남지 않는 것을 확인했습니다.

이 요청만 페이지와 다른 출처로 나가는데 거래소 API는 CORS를 허용하지 않으므로,
콘텐츠 스크립트가 아니라 서비스 워커(`background.js`)가 대신 보냅니다. 로그인 정보는
보내지 않습니다.

### 안 될 때

| 표시 | 뜻 |
| --- | --- |
| 영문 거래소에서 이 아이템을 찾지 못했습니다 | 판매가 내려갔거나 아직 영문 거래소에 없음 |
| 요청 한도 초과 | 아래 [요청 제한](#요청-제한) 참고. 안내한 초만큼 기다리면 됩니다 |
| 확장을 새로고침했습니다 | 확장을 다시 로드한 뒤라 페이지를 새로 열어야 합니다 |

같은 아이템을 다시 누르면 처음 받아 둔 값을 쓰므로 요청이 나가지 않습니다.

## 16T 8모드 검색 만들기

사이드바의 **16T 8모드 검색 만들기**를 펼치면 거를 맵모드를 골라 거래소 검색과
인게임 정규식을 한 번에 만들 수 있습니다.

1. 리그를 고르고 **거를 모드 고르기**를 누릅니다. 화면 가운데에 [모드 고르기 창](#모드-고르기-창)이
   열립니다.
2. 사이드바의 칸에 인게임 정규식이 실시간으로 만들어집니다. **복사**로 바로 쓸 수 있습니다.
3. **거래소 검색 만들기**를 누르면 검색이 등록되고 현재 탭이 결과로 이동합니다.
4. 이동하면 페이지가 다시 로드되지만, 만든 검색의 이름과 정규식은 잠시(10분)
   보관해 두었다가 위쪽 저장 폼에 다시 채웁니다. 저장하면 정규식도 함께 보관되고,
   목록의 **정규식** 버튼으로 언제든 다시 복사할 수 있습니다.

### 모드 고르기 창

모드는 80개인데 사이드바는 360px입니다. 한 줄씩 훑으면 원하는 모드를 찾기 어려워서,
고를 때만 화면 가운데에 넓은 창을 엽니다(**Esc**, **닫기**, 바깥 클릭, **완료** 중
아무거나로 닫습니다. 고른 내용은 그때그때 저장되므로 어떻게 닫아도 잃지 않습니다).

| 창 안의 것 | 하는 일 |
| --- | --- |
| 모드 검색 | 문구·접두어 이름 부분일치, `원소.가` 같은 [인게임 정규식꼴](#정규식으로-선택하기-역방향)도 받음 |
| 프리셋 | [프리셋](#프리셋)을 한 번에 적용 |
| 저장… | 지금 고른 모드를 [내 프리셋](#내-프리셋)으로 저장 |
| 삭제 | 고른 내 프리셋을 목록에서 지움 (기본 프리셋을 고르고 있으면 잠김) |
| 정규식으로 선택 | 인게임 정규식을 붙여넣어 [역으로 선택](#정규식으로-선택하기-역방향) |
| 전체 / 고른 것만 | 목록에 무엇을 보일지. 창을 열 때는 늘 **전체**부터 시작합니다 |
| 전체 해제 | 고른 모드를 모두 해제 |

목록 바로 위에 지금까지 고른 개수(`10개 고름`)가 있고, 그 옆이 보기 전환, 오른쪽 끝이
전체 해제입니다 — 목록에 관한 것만 한 줄에 모아 두었습니다.

모드는 화면 폭에 맞춰 여러 칸으로 늘어놓고, 계열 제목(`몬스터 강화`, `방어 약화` …)은
칸 전체에 걸쳐 붙어 스크롤해도 어디를 보고 있는지 알 수 있습니다. 고른 모드는 색으로
표시되고, 흔히 거르는 모드에는 **★** 가 붙습니다. 항목에 마우스를 올리면 접두어 이름과
한 항목이 묶고 있는 모드 문구 전부가 보입니다. 창 아래에는 지금까지 만들어진 인게임
정규식과 글자 수가 실시간으로 나옵니다.

만들어지는 검색 조건:

| 항목 | 값 |
| --- | --- |
| 아이템 유형 | 지도 |
| 아이템 희귀도 | 모든 비고유 (`nonunique`) — 8모드는 희귀 지도에만 붙습니다 |
| 지도 등급 | 16 (min=max) |
| 속성 부여 개수 | 8개 이상 (`pseudo.pseudo_number_of_affix_mods`) |
| 거래 옵션 | 즉시 구입 (`status.option = securable`) |
| 영향력 | 없는 지도만 — 영향력 implicit을 `not` 그룹으로 제외 |
| 거를 모드 | 선택한 모드를 `not` 스탯 그룹에 모두 포함 |

영향력은 거래소의 체크박스 필터로는 거를 수 없습니다. 필터 목록에 영향력 항목이
아예 없고, `pseudo` 영향력 스탯은 지도에 걸리지 않습니다(지도 매물에는 `influences`
속성이 없고 `Area is influenced by The Shaper` 같은 implicit 모드로만 표시됩니다).
그래서 `trade-query.js`의 `INFLUENCE_IDS`에 implicit id를 직접 적어 두고 제외합니다.
쉐이퍼·엘더·정복자 4종·전체 영향력·근원의 기억까지 8개입니다.

정규식은 `!대상이|재사용` 형태입니다. `!`는 부정(고른 모드가 **없는** 지도만 표시),
`|`는 나열, `.`은 공백 자리의 와일드카드입니다. 인게임 검색창 한도인 250자를
넘으면 글자 수 표시가 붉게 바뀝니다.

### 정규식으로 선택하기 (역방향)

반대 방향도 됩니다. [모드 고르기 창](#모드-고르기-창)의 정규식 칸에 인게임 정규식을
붙여넣고 **정규식으로 선택**을 누르면(Enter도 됨) 그 정규식에 걸리는 맵모드가 목록에서
그대로 체크됩니다.
이 확장이 만든 정규식뿐 아니라 [poe.re](https://poe.re/) 등 다른 도구나 친구에게
받은 것도 됩니다 — 인게임 문법(`!` 부정, `|` 나열, `.` 와일드카드, 공백으로 항목
구분, `"따옴표"` 묶음)을 그대로 해석합니다.

- 붙여넣은 정규식이 곧 선택 전체이므로 기존 선택은 대체됩니다.
- 넓은 패턴이 여러 모드에 걸리면 전부 선택합니다. 인게임에서도 전부 숨겨지므로
  그게 맞는 동작입니다.
- 모드 문구의 수치 구간(`(22—25)%`)은 실제 아이템에서 한 값(`23%`)으로 찍히므로,
  숫자 자리를 `.`으로 둔 패턴(`피해...%`)도 값을 채운 표본에 대조해 찾아냅니다.
- 어느 모드에도 안 걸리는 패턴은 상태 줄에 따로 알려 줍니다.

창의 모드 검색 칸도 같은 문법을 받습니다. `원소.가`처럼 인게임 정규식꼴로 입력해도
해당 모드가 검색됩니다.

### 인게임 정규식 엔진

정규식을 해석하는 일은 `poe-regex.js`가 전담합니다. 자바스크립트의 `RegExp`에
그대로 넘기지 않고 직접 해석하는데, 게임의 규칙과 다른 자리가 있어서 `RegExp`로
맞추면 "걸린다"고 표시한 지도가 정작 인게임 필터에서는 안 걸리기 때문입니다.

게임이 쓰는 엔진은 **MSVC의 `std::regex`(ECMAScript 문법)** 입니다. 검색칸에서 곧바로
튀어나온 예외 대화상자의 문구가 microsoft/STL의 것과 한 글자도 다르지 않습니다
(`regex_error(error_complexity)`,
[근거](https://www.pathofexile.com/forum/view-thread/3195613)). 여기 적힌 문법은
대체로 그 사실에서 따라옵니다.

다른 자리는 세 곳입니다.

**1. 한 줄씩 맞춥니다.** 여러 줄을 한 덩어리로 보지 않으므로 `.`은 줄바꿈을 넘지
못하고, `^`와 `$`는 줄마다 걸립니다. 그래서 한 패턴이 서로 다른 두 모드 줄에 걸쳐
매칭되는 일이 없습니다.
([근거](https://www.pathofexile.com/forum/view-thread/3305826) — "The regex engine
always performs a single line match ... `(?m)` doesn't do anything")

**2. 글자 그대로 먼저 찾습니다.** 정규식으로 읽기 전에 입력을 그냥 부분 문자열로
찾아봅니다. `+94%`처럼 정규식으로는 깨진 검색어가 게임에서 멀쩡히 걸리는 이유입니다
([근거](https://devtrackers.gg/pathofexile/p/8e79558c-when-did-we-get-regex-search-in-tabs)
— "try a basic string match first, then attempt a regex match if the basic match
fails"). 그래서 문법이 깨진 패턴도 오류로 막지 않고 글자 그대로 맞춰 봅니다.

**3. 받는 문법이 다릅니다.**

| 문법 | 뜻 |
| --- | --- |
| 공백 | 항목 구분. 모든 항목을 만족해야 함 (AND) |
| `!` | 그 항목만 부정 |
| `"..."` | 공백이 든 문구를 한 항목으로 묶음 |
| `.` | 줄바꿈을 뺀 아무 글자 하나 |
| `\|` | 나열 |
| `()` `(?:)` | 묶음 |
| `[]` `[^]` | 문자 클래스, 범위 |
| `\d` `\w` `\s` `\D` `\W` `\S` | 축약 클래스 |
| `?` `*` `+` `{n,m}` | 수량자 |
| `^` `$` | 줄의 처음·끝 |
| `(?=)` `(?!)` | 전방 탐색 |
| `\` | 메타문자를 글자로 |

대소문자는 가리지 않고, 문구 어디에 있든 걸리는 부분 일치입니다. 전방 탐색과 `\d`가
실제로 통한다는 근거는 [poe.re](https://poe.re/)가 만들어 인게임에 그대로 붙여 넣게
하는 문자열입니다(`(?=(\S*r){2})`, `\d+`).

게임에서 어떻게 되는지 **알 수 없는** 문법은 매칭에서 빼고 따로 알립니다. 찍어서
맞추면 확장만 걸린다고 하고 게임은 아닌 어긋남이 생기기 때문입니다.

- **후방 탐색**(`(?<=)`, `(?<!)`): MSVC의 `std::regex`에 구현이 아예 없습니다.
- **역참조**(`\1`)와 **단어 경계**(`\b`): 문법상 있어야 맞지만 실제로 통했다는
  보고를 찾지 못했습니다. 지도 정규식에서 쓸 일도 없습니다.

되추적 대신 NFA 시뮬레이션으로 맞춥니다. `(가+)+나` 같은 패턴은 되추적으로 짜면
24글자에 6초가 걸리는데, 검색칸에는 아무 정규식이나 붙여 넣을 수 있으므로 그 한
줄에 사이드바가 멈춥니다. 전방 탐색은 그 자리에서 속을 따로 돌려 보는 방식으로
얹었고, 역참조를 받지 않으므로 패턴은 언제나 정규 언어입니다. 덕분에 가능한 자리를
한꺼번에 굴려 폭발 없이 끝납니다. (게임 쪽은 되추적이라 `((.*)*)` 같은 패턴이
실제로 클라이언트를 멈춥니다 — 위의 `error_complexity`가 그것입니다.)

### 거래소 검색과 인게임 필터를 맞추기

둘이 어긋나면 사 온 지도가 인게임 필터에서 사라집니다. 어긋나는 원인은 둘뿐입니다.

- **키워드가 다른 줄에 걸림**: 인게임 검색은 아이템 전문(이름·속성 줄·목록에 없는
  모드까지)을 훑습니다. 예전 `억제`는 다른 모드인 "플레이어가 방지하는 억제된 주문
  피해"에, `종류`는 "아이템 종류: 지도"에 걸려 멀쩡한 지도를 숨겼습니다.
- **stat id의 domain이 틀림**: 타락으로 붙는 모드는 `implicit.*`입니다.
  `explicit.*`로 적어 두면 거래소는 걸러 주지 않는데 인게임 필터만 숨깁니다.

그래서 키워드를 고치거나 추가할 때는 실제 매물 문구로 검증합니다. 거래소 매물의
`extended.text`가 곧 인게임 Ctrl+C 문구이므로, T16 지도를 여러 건 받아
`(정규식이 숨김) == (그 모드의 id를 가짐)`이 모든 매물에서 성립하는지 봅니다.
현재 목록은 실매물 200건 × 모드 80개에서 어긋남 0건입니다.

키워드 유일성은 `node --test`가 자동으로도 검증합니다. 일곱 방향으로 대조합니다.

| 대조 대상 | 잡아내는 사고 |
| --- | --- |
| 목록 안 모드 80개 서로 | 한 키워드가 다른 모드까지 숨김 |
| T16 풀 전체 86개 (`test/fixtures/map-mod-pool.json`) | 목록 밖 모드(타락·스컬지·탐광)에 걸림 |
| 실제 지도 세 장 (`test/fixtures/real-maps.json`) | 속성 줄·괄호 설명 줄에 걸림 |
| 고급 모드 설명 줄 (접두어 이름 79개 + 태그 19개) | 이름·태그와 같은 키워드가 엉뚱한 지도를 숨김 |
| 한 항목이 묶은 변종 전부 | `기절.면`이 `다산의`만 붙은 지도를 놓치던 사고 |
| 거래소 stat id (`test/fixtures/trade-stats.json`) | id를 잘못 적어 거래소만 안 걸러 주던 사고 |
| 지도 칸 아이템 이름 519개 (`test/fixtures/map-item-names.json`) | `사로잡`이 갑충석 `사로잡힘의 고통`을 숨기던 사고 |

풀 픽스처는 [poedb의 11~17등급 표](https://poedb.tw/kr/Maps_top_tier)에서 받아
박아 둔 것입니다. 리그가 바뀌어 풀이 달라지면 다시 받아 갱신해야 합니다.

**고급 모드 설명**을 켜면 모드마다 이런 줄이 앞에 붙습니다.

```
{ 접미어 속성 부여 "- 독액" (등급: 1) — 카오스, 상태 이상 }
몬스터의 공격 명중 시 중독 — 변경이 불가능한 값
```

접두어 이름과 태그가 그대로 들어 있고, **인게임 검색은 이 줄도 읽습니다.**
`test/real-map.js`의 지도를 창고에서 `변덕`으로 검색하면 걸리는데, 그 지도에서
`변덕`이 있는 곳은 `{ 접두어 속성 부여 "변덕스러운" (등급: 1) }` 한 줄뿐입니다.
모드 문구는 "지역에 염소인간 서식"이라 `변덕`이 없습니다.

그래서 이름이나 태그와 같은 키워드는 그 모드가 없는 지도까지 숨깁니다.
`냉기`·`번개`·`화염`·`상태`·`동결`·`사술`·`노출` 일곱 개가 여기 해당해서 안전한
부분문자열로 바꿨습니다.

이 줄은 켜고 끄는 설정이 아닙니다(그런 설정은 없습니다). Alt를 누르고 있을 때
툴팁에 보이고 `Ctrl+Alt+C`로 복사되는, 아이템이 늘 갖고 있는 정보입니다. 인게임
검색은 그 전문을 훑으므로 접두어 이름과 태그도 언제나 검색 대상입니다.

희귀 지도에는 무작위로 만든 이름(`운명의 도전` 같은)이 한 줄 더 붙는데, 그 낱말
목록은 구하지 못해 검사로 막을 수 없습니다. 그래서 **키워드를 한글 3글자 이상**으로
씁니다. 2글자는 그런 이름에 걸릴 확률이 무시할 수준이 아니기 때문입니다.

길이는 문제가 되지 않습니다. 맵모드를 열 개 넘게 거는 일이 드문데, 12개를 골라도
58자로 인게임 한도 250자의 4분의 1입니다. 30개까지 골라도 141자입니다.

| 고른 모드 수 | 정규식 길이 |
| --- | --- |
| 8개 | 39자 |
| 12개 | 58자 |
| 20개 | 95자 |
| 30개 | 141자 |
| 80개(전부) | 373자 — 한도 초과, 글자 수 표시가 붉어집니다 |

### 내 프리셋

모드를 골라 둔 상태에서 **저장…** 을 누르고 이름을 적으면 그대로 프리셋이 됩니다. 드롭다운
아래쪽 **내 프리셋** 묶음에 들어가고, 고르면 기본 프리셋과 똑같이 적용됩니다.

- 이미 있는 이름으로 저장하면 새로 만들지 않고 **덮어씁니다** — 이름이 곧 그 프리셋입니다.
- 기본 프리셋과 같은 이름은 쓸 수 없습니다. 어느 쪽을 고른 것인지 알 수 없어집니다.
- **삭제** 는 목록에서만 지웁니다. 지금 고른 모드는 그대로 남습니다.
- `chrome.storage.local`의 `userPresets`에 `{ id, label, keys, at }`로 저장됩니다. `keys`는
  기본 프리셋과 같은 형식이라, 리그가 바뀌어 모드 목록이 달라지면 없어진 모드는
  `모드 목록에 없는 N개는 건너뜀`으로 알려 줍니다.

### 프리셋

기본 프리셋은 `presets.js`에 정의합니다.

| 프리셋 | 내용 |
| --- | --- |
| 일반 추천 | 빌드와 무관하게 흔히 거르는 10개 |
| 내 빌드 (윈터 오브) | 엘리멘탈리스트 냉기 주문 빌드에 맞춘 11개 |

**윈터 오브 프리셋**은 PoB 빌드(`my wo 2`)의 실제 수치를 근거로 골랐습니다.

저주는 서리 저주(사술)와 암살자의 징표(표식)를 비전학자의 낙인으로 시전하는데,
저주 한도를 올리는 아이템·패시브가 없어 기본 1이고 표식도 같은 한도를 쓰므로
실제로는 한 번에 하나만 걸립니다. 사술 방지는 이 중 서리 저주만 막습니다.

넣은 것:

| 모드 | 이유 |
| --- | --- |
| 원소 피해 반사 | 피해가 전부 냉기 |
| 몬스터의 원소 저항 +40% | 냉기 딜이 그대로 깎임 |
| 재생 불가 | 마나 재생 140/s로 채널링 유지 (소모 154/s) |
| 생명력·ES 회복 속도 감폭 | 흡수가 0이라 회복이 유일한 수단 |
| 모든 저항 최대치 감소 | 원소 저항 75 고정 |

| 저주 효과 감폭 | 사술·표식 모두 약화 — 저주가 냉기 저항 감소의 주 출처 |

일반 추천에서 뺀 것 — 이 빌드에는 영향이 없습니다.

| 모드 | 뺀 이유 |
| --- | --- |
| 몬스터는 흡수 대상이 되지 않음 | 생명력/마나/ES 흡수가 전부 0 |
| 플레이어의 정확도 감폭 | 주문이라 명중 굴림이 없음(명중 100%) |

### 데이터 출처

`map-mods.js`(한글)는 아래를 합쳐 생성했습니다.

- 모드 풀과 한글 표기: [poedb Maps_top_tier](https://poedb.tw/kr/Maps_top_tier)
- 거래소 stat id: `/api/trade/data/stats`의 `explicit` 그룹
- 정규식 규칙: [POE Regex KR](https://poeregexkr.web.app/)

`map-mods-en.js`(영문)는 같은 모드를 같은 순서로 담고 문구·이름·키워드만 다릅니다.
문구를 지어내지 않으려고 두 언어를 함께 내놓는 출처만 썼고, 서로 대조했습니다.

- 모드 풀과 영문 표기: [poedb Maps_top_tier](https://poedb.tw/us/Maps_top_tier)의 영문판
  — 한글판과 같은 표라서 항목 순서가 같습니다. 생성 스크립트가 매번 한글판을 다시 뽑아
  `test/fixtures/map-mod-pool.json`과 대조해 그 가정을 확인합니다.
- 대조: [awakened-poe-trade](https://github.com/SnosMe/awakened-poe-trade)의 언어별 스탯
  데이터 — 80개 중 78개가 두 출처에서 일치합니다(나머지 둘은 대조할 데이터가 없는
  경우로, `data/en/README.md`에 적어 두었습니다).

각 모드의 정규식 키워드는 두 언어 모두 T16 모드 전체를 대상으로 "그 모드에만
매칭되는 최단 부분문자열"을 계산한 값입니다. 지도마다 값이 달라지는 숫자는 키워드에서
제외하고, 목록 밖 모드·지도 칸 아이템 이름·고급 모드 설명 줄·속성 줄에도 걸리지
않는지 검사합니다(`node --test`).

만드는 스크립트는 `tools/`에 있습니다.

```
node tools/build-en-data.js       # 영문 모드 풀·문구·대조표 만들기
node tools/build-map-mods-en.js   # 그 데이터로 map-mods-en.js 만들기
```

### 요청 제한

거래소 검색 등록은 **계정 5초당 3회, IP 60초당 15회**로 제한됩니다. 확장은 검색
버튼에 2.5초 최소 간격을 두고, 429 응답을 받으면 `Retry-After` 값을 안내합니다.

영문 아이템 조회(EN 단추)는 별도로 **IP 4초당 12회, 5분당 50회**입니다. 한 번 받은
아이템은 기억해 두므로 같은 아이템을 다시 눌러도 요청이 늘지 않습니다.

북마크 이름을 채울 때는 요청을 보내지 않습니다. 페이지의 검색 폼만 읽습니다.

## 권한

확장 권한은 `storage` 하나이고, 여기에 `https://www.pathofexile.com/*`에 대한
`host_permissions`가 더해집니다. 이 호스트 권한은 오직 EN 단추가 영문 아이템 정보를
읽어 오는 데만 쓰이며, 그 요청에는 로그인 정보를 붙이지 않습니다.

패널은 `content_scripts.matches`에 적힌 위 사이트의 `/trade/` 경로에서만 실행되고,
그 외 사이트에는 아무것도 넣지 않습니다. 나머지 거래소 API 호출(리그 목록, 검색 등록)은
페이지와 같은 출처로 나가므로 별도의 권한이 필요하지 않습니다.

사이드바는 Shadow DOM 안에서 그려지므로 거래소의 CSS와 서로 영향을 주지 않고,
그 안에서 누른 키는 거래소의 전역 단축키로 새어 나가지 않습니다. 페이지를 밀어낼
때 건드리는 것은 `<html>`의 `margin-right` 하나뿐입니다.

사이트를 추가하려면 `manifest.json`의 `content_scripts.matches` /
`web_accessible_resources.matches`와 `trade-url.js`의 `TRADE_HOSTS`를 함께
수정해야 합니다.

## 저장 방식

`chrome.storage.local`에 아래 형태로 저장됩니다. 확장을 삭제하면 함께 지워집니다.
북마크는 `bookmarks`, 검색 기록은 `history`(최대 50개), [내 프리셋](#내-프리셋)은
`userPresets`, [언어](#언어) 설정은 `lang`(`auto`/`ko`/`en`)에 들어갑니다.

```json
{
  "id": "uuid",
  "title": "표시 이름",
  "url": "https://www.pathofexile.com/trade/search/<리그>/<검색ID>",
  "league": "리그명",
  "mode": "search | exchange",
  "searchId": "검색ID",
  "summary": {
    "item": "괴사의 방어구",
    "filters": [{ "label": "타락함", "value": "아니오" }],
    "ranges": [{ "label": "지도 등급", "type": "", "min": "16", "max": "16" }],
    "statGroups": [
      { "title": "모두 일치", "rows": [{ "label": "생명력 최대치 +#", "type": "", "min": "100", "max": "", "value": "" }] }
    ]
  },
  "createdAt": 1700000000000,
  "updatedAt": 1700000000000
}
```

기록 항목은 `createdAt`/`updatedAt` 대신 마지막으로 검색한 때인 `at`을 갖습니다.
`summary`는 보여 줄 문구가 아니라 읽어 낸 구조 그대로입니다 — 표시 형태를 바꿔도
이미 저장한 항목이 그 형태를 따라오게 하려는 것입니다. 조건을 못 읽었으면 아예
없습니다.

### 테스트

```
node --test
```

받아 올 것이 없습니다. 노드에 들어 있는 러너(`node:test`)만 쓰므로 이 저장소에는
`package.json`도 `node_modules`도 없습니다.

콘텐츠 스크립트끼리는 서로를 `require`하지 않습니다. 브라우저에서는
`manifest.json`이 정한 순서대로 `<script>`가 로드되고 전역을 그대로 나눠 쓰기
때문입니다. 그래서 테스트가 그 순서를 대신 깔아 줍니다. 파일을 새로 추가하면
`manifest.json`의 `js` 목록에도 **순서에 맞게** 넣어야 합니다.
